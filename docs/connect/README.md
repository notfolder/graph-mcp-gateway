# AI ツールからの接続（共通）

社内共有 M365 MCP サーバーには、受け口（MCP のエンドポイント）が 2 つある。どちらも Entra ID（社内アカウント）でサインインし、鍵の配布は無い。

| 受け口 | URL | 見えるツール | 向いている使い方 |
|---|---|---|---|
| 全部を出す受け口 | `https://<公開のホスト名>/full/mcp` | ms-365-mcp-server のツール全部（約 170 個、一覧は約 1 MB） | ツールを直接呼びたい。AI ツールの入力の上限に余裕がある |
| 探して使う受け口 | `https://<公開のホスト名>/discovery/mcp` | 「ツールを探す」「引数を調べる」「実行する」の 3 つ（＋管理者が決めた直接出すツール） | ツールの一覧が大きくて入力に収まらない。言語モデルに探してから使わせたい |

迷ったら探して使う受け口を使う。両方を登録してもよい（受け口ごとに 1 回ずつサインインが要る）。

## 共通の流れ

1. AI ツールに受け口の URL を登録する（手順は AI ツールごとの文書）。
2. 認証を始めると、ブラウザで本システムの「接続の確認」画面が開く。AI ツールの名前を確かめて「許可」を押す。
3. Entra ID のサインイン画面で社内アカウントでサインインする（PoC 参加者として割り当てられていない人は拒否される）。
4. AI ツールに戻ったら、「自分のプロフィールを取得して」などと頼み、本人の情報が返ることを確かめる。

## 社内の認証局を信頼させる

本システムのサーバー証明書は社内の認証局が発行している。AI ツールがその認証局を信頼していないと、証明書のエラーで接続できない。社内の認証局の証明書（PEM）を手元に置き、AI ツールごとの設定で読ませる。

| AI ツール | 設定 |
|---|---|
| Claude Code | 環境変数 `NODE_EXTRA_CA_CERTS=<社内の認証局の PEM のパス>` |
| Codex | 環境変数 `CODEX_CA_CERTIFICATE=<社内の認証局の PEM のパス>` |
| OpenCode | 環境変数 `NODE_EXTRA_CA_CERTS=<社内の認証局の PEM のパス>` |

## うまくいかないとき

| 症状 | 確かめること |
|---|---|
| 証明書のエラー | 上の「社内の認証局を信頼させる」の設定 |
| サインインで拒否される（AADSTS50105） | PoC 参加者として割り当てられているか（管理者に連絡） |
| 401 が続く | 認証をやり直す（AI ツールの MCP の認証の操作） |
| ツールの一覧が入力に収まらない | 探して使う受け口に切り替える |
